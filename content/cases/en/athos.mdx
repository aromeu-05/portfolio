<Chapter id="probleme" title="The problem">

Reviewing one file took 30 minutes to an hour in Priméo, Effy's old tool, including about 10 minutes per document.

A file mixes quotes, invoices, tax notices and certificates, often sent more than once. The reviewer checks each document against an official spec sheet for the type of work. They also check that documents match each other: same address, same amount, a quote signed before the work started.

ATHOS takes a different approach. The AI extracts the data, applies the rules and sorts each file:

<StatusList items={[
  ["ok", "green", ": compliant, it goes to audit;"],
  ["warn", "orange", ": something needs the reviewer's eye;"],
  ["ko", "red", ": a document is non-compliant, and the client or contractor has to be contacted."],
]} />

Two constraints framed the design. A false positive is costly, because the file is regulated. And Effy wanted a very guided flow: some reviewers were redoing checks that didn't need redoing.

<Question>How do you make the AI's work verifiable in a few seconds, without the reviewer redoing everything?</Question>

</Chapter>

<Chapter id="role" title="My role">

I was the only designer on the project, from the review flow down to the detailed screens.

The project ran on two parallel tracks: AI and business logic on one side, design on the other. Every week, I presented my mockups to Effy's head of operations and to a former reviewer. Their feedback shaped the next version.

I designed:

- the reviewer's portfolio (“My files”);
- the file review screen;
- file assignment and statistics;
- the back office: CEE spec sheets and user management.

</Chapter>

<Chapter id="d1" decision="Decision 01" title="Every alert ends with a human decision">

I turned each AI alert into a card that ends with Approve or Reject. A “point to check” card contains:

- the AI's explanation, in plain language (“the quote says ‘Docteur Millet’, the invoice ‘docteur millet’: case mismatch”);
- links to the documents involved;
- a confidence score;
- a specific question, then two answers.

<Figure src="/images/effy/web/effy-03-carte-point-zoom.jpg" height={960} caption="The “point to check” card, annotated" />

The first version had a third button, “Suggest to AI”. I removed it to align the card with the review model we had agreed on with Effy. A document “to review” can only end up approved or rejected. The reviewer always stays in control: rejecting doesn't send anything automatically.

The AI then drafts the request for missing information. The reviewer reads it, edits it if needed, and sends it.

<Chapter id="d2" decision="Decision 02" title="Alert, data and proof side by side">

The file view went from two columns to three: alerts, extracted data, source document.

The tender version showed the alerts and the document. It was missing the form sections: the fields the reviewer has to fill in to generate the certificate. But with Effy, we had defined the first compliance criterion for a file: no missing information in those sections. So they moved to the center of the screen.

In the form sections:

- a wand icon marks each field the AI pre-filled, which stays editable;
- an empty required field turns red, but only if it's expected at that stage. An invoice field isn't, until the invoice has arrived;
- a field the reviewer filled in by hand counts as valid.

In the document, a marker points to the area the information came from. The alerts panel collapses while keeping its counters, to make room for the document.

**The reviewer no longer searches for anything: they see the alert, the value and the proof in one place.**

</Chapter>

<Chapter id="d3" decision="Decision 03" title="The AI's colors organize the whole portfolio">

The green, orange, red code isn't only used inside a file: it sorts the day's work. The “My files” page answers one question: what should I handle first?

- tabs by color, each with its file count, sorted by priority by default;
- three metrics at the top: files to check, non-compliant files, and files overdue by more than 72 hours;
- in the table, the file's stage, its completion rate, the time since the last submission, and the AI's alerts as badges;
- saved views to get back to a set of filters.

<Figure src="/images/effy/web/effy-04-portefeuille.jpg" caption="The “My files” page" />

The “by contractor” view came from Effy's feedback at the first design review. One contractor can have fifteen open files, five of them red. The reviewer calls them once about all of them, not file by file. So files are grouped by installer.

Sorting by the date of the last document received also came from Effy: that's how they measure delay.

</Chapter>
